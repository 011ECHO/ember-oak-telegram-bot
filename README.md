# ☕ Ember & Oak — Telegram Order Bot

A Telegram bot for the fictional coffee shop **Ember & Oak** that lets customers
browse a menu, build a cart and place an order, while notifying an administrator
who can accept or reject each order in one tap.

Built with **Python 3.11+**, **[aiogram 3.x](https://docs.aiogram.dev/)** and
**SQLite** (async via `aiosqlite`).

---

## ✨ Features

- **Multi-language interface** — 🇷🇺 Russian, 🇬🇧 English, 🇪🇸 Spanish. The bot
  asks for a language on first contact (pre-guessed from the Telegram client),
  stores the choice per user, and lets them change it anytime with **/language**.
- **Native command menu** — the blue **Menu** button next to the input field
  lists the bot's commands, localized per language; admins get extra commands.
- **Persistent bottom bar** — an always-available reply keyboard (🍽 Menu ·
  🛒 Cart · 🌐 Language) toggled by the grid icon next to the input field, the
  way large bots expose quick actions.
- **/start** — greeting with an inline **Menu** button.
- **Menu with categories** (☕ Coffee · 🥐 Pastry · 🍳 Breakfast) — tap a category
  and all of its products appear at once as **photo cards** (image + description
  + price + an add-to-cart / quantity control under each). Images live in
  `images/<id>.png` and are swappable with real photos (no code change); the
  included placeholders are generated by `tools/generate_placeholder_images.py`.
- **Cart** — item list with quantities, per-item and total price, inline
  **➕ / ➖ / ❌** controls and a **Checkout** button.
- **Checkout (FSM)** — asks for a name (only if it's missing from the Telegram
  profile), a phone number (via the native *Share contact* button or typed in),
  and an **optional order comment** (allergies, preferences — with a Skip
  button). The comment is shown in the summary and on the admin card.
- **Contact / feedback** — a **💬 Contact** button (and `/feedback`) shows the
  café's contact info and lets the customer send a message that is delivered to
  every staff member, with a one-tap link to reply.
- **Online payment (optional)** — with a payment provider configured, the summary
  offers **💳 Pay online** (native Telegram Payments — card entered right in the
  chat) and **💵 Pay on pickup**. Paid orders are created only after Telegram
  confirms the payment, and the admin card shows the payment status. Disabled
  automatically when no provider token is set.
- **Order stored in SQLite** — after confirmation the customer sees
  *"Order #N placed — being processed"* (the order is **not** marked accepted
  until an admin confirms it).
- **Admin notification** — every new order is sent to **all** administrators with
  the customer's **@username** and a **✍️ message-the-customer** link, plus
  **✅ Accept** / **❌ Reject** buttons. The decision updates the order status and
  notifies the customer *in their own language* (accepted / rejected).
- **/admin** — list of the last 10 orders with their statuses (admin only).
- **/stats** — number of orders today and today's revenue (admin only).
- **In-bot menu editor** (`/editmenu`, managers only) — add products (name, price,
  emoji, description — the card image is generated automatically), change prices,
  mark items **out of stock** (shown greyed, can't be ordered) or **hide** them,
  and delete them. The menu lives in the database and updates instantly for
  customers — no code or redeploy needed.
- **Role-based staff (super admin / admin / moderator)**:
  - **super admin** — the `ADMIN_CHAT_ID` from the environment; manages everyone
    and can never be removed;
  - **admin** — receives orders, accepts/rejects, and can add/remove admins and
    moderators;
  - **moderator** — receives orders and accepts/rejects only; cannot manage staff.

  Managers add staff by id (**/addadmin `<id>`**, **/addmod `<id>`**) and remove
  them by **picking a person from an inline list** in the **/staff** panel — no
  need to type an id. Whoever is promoted or demoted gets a message from the bot,
  in their own language.

## 📁 Project structure

```
ember_oak_bot/
├── bot.py             # entry point: builds the bot and starts polling
├── config.py          # environment / settings loading (.env)
├── locales.py         # i18n translations (ru/en/es) + t() helper
├── menu.py            # DB-backed, editable menu (cache + async mutators)
├── images_gen.py      # product-card image generation (Pillow)
├── database.py        # async SQLite layer (orders, users, admins, products)
├── states.py          # FSM states for the checkout flow
├── callbacks.py       # typed inline-button callback data
├── cart.py            # cart logic stored in the FSM context
├── keyboards.py       # inline & reply keyboard builders
├── botcommands.py     # native "Menu" command button setup
├── notifications.py   # order-message formatting & admin notification
├── handlers/
│   ├── __init__.py
│   ├── user.py        # customer handlers (language, menu, product cards, cart, checkout, payment)
│   ├── admin.py       # admin handlers (/admin, /stats, accept/reject, staff mgmt)
│   └── menu_admin.py  # in-bot menu editor (/editmenu, managers)
├── images/            # one <product_id>.png per item (swap in real photos here)
├── tools/
│   └── generate_placeholder_images.py  # dev tool that (re)builds the placeholders
├── requirements.txt
├── .env.example       # sample environment file
├── .gitignore
└── README.md
```

## 💬 Commands

| Command             | Who        | What it does                                   |
| ------------------- | ---------- | ---------------------------------------------- |
| `/start`            | everyone   | Start the bot / choose language / show menu    |
| `/menu`             | everyone   | Open the menu categories                       |
| `/feedback`         | everyone   | Show café contacts and send a message to staff |
| `/language`         | everyone   | Change the interface language                  |
| `/admin`            | staff      | List the last 10 orders                        |
| `/stats`            | staff      | Today's order count and revenue                |
| `/staff`            | staff      | Staff list + roles; remove members via a picker |
| `/editmenu`         | managers   | Add/edit products, prices, availability        |
| `/addadmin <id>`    | managers   | Add an administrator by numeric Telegram ID    |
| `/addmod <id>`      | managers   | Add a moderator by numeric Telegram ID         |

## 🚀 Getting started

### 1. Requirements

- Python **3.11 or newer**

### 2. Clone & install dependencies

```bash
git clone <your-repo-url>
cd ember_oak_bot

# Create and activate a virtual environment (recommended)
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### 3. Create your `.env` file

Copy the example and fill in your values:

```bash
# Windows (PowerShell)
Copy-Item .env.example .env
# macOS / Linux
cp .env.example .env
```

```env
BOT_TOKEN=123456789:AA...your-token-here
ADMIN_CHAT_ID=123456789
```

- **`BOT_TOKEN`** — get it from [@BotFather](https://t.me/BotFather) by creating
  a new bot (`/newbot`).
- **`ADMIN_CHAT_ID`** — your personal numeric Telegram ID. The quickest way to
  find it is to message [@userinfobot](https://t.me/userinfobot).

> The `.env` file and the SQLite database (`*.db`) are excluded from git via
> `.gitignore`, so your secrets and data never get committed.

### 4. Run the bot

```bash
python bot.py
```

Open your bot in Telegram, send **/start**, and place a test order. The order
will pop up in the admin chat with Accept / Reject buttons. 🎉

## 🛠 Tech notes

- **Cart storage** — the cart lives in aiogram's per-user FSM data as a simple
  `{product_id: quantity}` map, so it persists while browsing and is cleared once
  an order is placed.
- **Callback data** — inline buttons use aiogram's `CallbackData` factories
  (`callbacks.py`) for structured, type-safe payloads instead of ad-hoc strings.
- **Orders** are stored in a single `orders` table; line items are kept as a JSON
  column, keeping the schema minimal while recording exactly what was ordered.

## ⚙️ Configuration reference

| Variable        | Required | Default         | Description                                     |
| --------------- | -------- | --------------- | ----------------------------------------------- |
| `BOT_TOKEN`     | ✅       | —               | Bot token from @BotFather                       |
| `ADMIN_CHAT_ID` | ✅       | —               | Numeric Telegram ID of the administrator        |
| `DB_PATH`       | ❌       | `ember_oak.db`  | Path to the SQLite database file                |
| `PAYMENT_PROVIDER_TOKEN` | ❌ | —          | Telegram Payments provider token; enables online payment |
| `PAYMENT_CURRENCY` | ❌    | `EUR`           | ISO-4217 currency used for invoices             |

### 💳 Enabling online payment (optional)

1. In [@BotFather](https://t.me/BotFather): `/mybots` → your bot → **Payments** →
   pick a provider (e.g. **Stripe**). For a risk-free demo choose **Stripe TEST**.
2. Copy the **provider token** BotFather gives you into `.env` as
   `PAYMENT_PROVIDER_TOKEN=...` and restart the bot.
3. Place an order and choose **💳 Pay online**. In test mode, pay with the Stripe
   test card **`4242 4242 4242 4242`**, any future expiry, any CVC — no real money
   moves. The same code goes live by swapping in a production provider token.
